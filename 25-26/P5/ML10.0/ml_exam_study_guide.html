Two key spaces

Model space: each point = one model (a specific set of parameters). Search happens here.

Feature space: each point = one instance. Dimensionality = number of features. Classification draws a boundary here.

Search methods
  • Random search — no gradient needed; slow; works for discrete/non-differentiable models
  • Gradient descent — fast; needs differentiable loss; can get stuck in local minima
  • EM algorithm — alternating optimization; used in GMMs and VAEs
  • ID3 (greedy) — decision trees; picks best split at each step
Exam format reminder

40 questions × 1pt. Three equal categories: Recall (memorize definitions), Combination (reason across concepts, often phrased negatively — "which is NOT…"), Application (compute: entropy, backprop, rankings, Naive Bayes, SVM, Markov). Application questions follow fixed patterns — master the 10 types.

Methodology
Evaluation, validation, performance metrics — frequently tested
Train / validation / test split

Why? Reusing the test set inflates performance estimates and overfits to random effects (Rob's mistake with k=17).

During model/hyperparam selection: train on train, evaluate on validation.
Final report: train on train+val, test on withheld test set — only once.

Hyperparameters (e.g. k in kNN, max depth in trees) are tuned using the validation set — never the test set.

Ranking & coverage — application type

For a linear classifier, rank by distance to decision boundary (the raw score w·x + b).

Ranking error = a (pos, neg) pair where neg is ranked above pos
Coverage = ranking errors / (# pos × # neg)

E.g. 4 pos, 4 neg → max 16 possible ranking errors. If 2 errors → coverage = 2/16 = 1/8.

Common pitfall: students confuse total pairs with ranking errors. Draw the coverage matrix to be safe.
Class & cost imbalance

Class imbalance: unequal numbers of pos/neg instances in data.

Cost imbalance: misclassifying different classes has different real-world costs (e.g. spam classifier that deletes — a false positive is catastrophic). Accuracy alone is misleading here.

Accuracy optimization is dangerous when costs differ, even if the class distribution is balanced.
Preprocessing
  • Normalization / standardization — rescale features to similar range; needed for gradient-based & distance-based methods
  • PCA — can also normalize (whitening); primarily for dimensionality reduction
  • Imputation — handle missing values; NOT for normalization (common trick-question!)
  • Outlier removal — remove from training if they distort the model; keep in test set for realistic eval
Overfitting & regularization
  • Overfitting: model memorizes training data, fails on test data
  • L1 regularization: adds |w| penalty → sparse weights
  • L2 regularization: adds w² penalty → small weights
  • Dropout: randomly zero out nodes during training
  • Max depth in trees: limits model complexity, reduces overfitting

L1/L2 require real-valued parameter vectors — can't apply to decision trees (discrete model space).

Imbalanced classes — undersampling vs oversampling
  • Undersampling: drop random instances of the MAJORITY class until balanced. No duplicates, but loses data.
  • Oversampling: REPEAT instances of the MINORITY class until balanced. Creates duplicate rows.
  • Both before splitting risks data leakage — apply only on the training set.
  • Stratified k-fold preserves the original class ratio in each fold.
Past-exam fact (final-2022 Q4): "Oversampling leads to duplicate instances in your data." (Undersampling does not.)
Categorical features — integer vs one-hot coding
  • Integer coding: assign 0,1,2,… to each category → 1 numeric column. Imposes a fake ordering.
  • One-hot coding: 1 binary column per category → k categories give k columns. Always TURNS ONE FEATURE INTO MULTIPLE.
  • One-hot becomes inefficient when there are too many categories (sparse, wide).
  • Integer coding works only if a true ordering exists (small, medium, large).
Probability foundations — sample / event space, frequentist / Bayesian

Sample space = set of atomic outcomes (rolling a die: {1,…,6}). Event space = subsets of outcomes ("rolling an even number" = {2,4,6}).

  • Frequentist: probability = long-run frequency of repeatable random events. A fixed quantity (like the mean Italian woman's height) is NOT random → frequentist rejects "the mean has high probability of being < 2 m."
  • Bayesian: probability = degree of belief; can be assigned to fixed unknowns.
  • Subjectivist: probability = personal credence; even more permissive than Bayesian.
Past exam (final-2022 Q6): "There is a high probability that the mean height of Italian women is below 2 m." → A strict frequentist would reject this as improper use.
Time-series & recommender quirks
  • Walk-forward validation: train on t≤T, test on T+1; then include T+1 in training, test on T+2; repeat. Respects time order; lets the model retrain.
  • Cold-start problem (recommenders): a brand-new user/item has no rating history → matrix factorisation cannot learn an embedding for it. Mitigations: hybrid models with content/side features, popularity baselines.
Linear models & loss functions
Hyperplanes, gradient descent, and which loss to use when
Linear model anatomy
f(x) = w·x + b = Σᵢ wᵢxᵢ + b
  • w: weight vector — perpendicular to decision boundary
  • b: bias — shifts boundary from origin
  • Decision boundary: set of x where w·x + b = 0
  • Classification: predict Pos if w·x+b > 0, else Neg
Gradient descent
w ← w − η∇loss(w)
  • η (learning rate): typically 0.0001 – 0.1
  • Requires differentiable loss
  • Convex loss → guaranteed global minimum
  • Non-convex → local minima possible
  • SGD: one instance at a time; noisy but fast
  • Minibatch GD: compromise between GD and SGD

Find the gradient — application type

Always use the chain rule step by step. For model y = f(x; θ), loss = ½Σ(yᵢ−tᵢ)²:

∂loss/∂θ = Σᵢ (yᵢ−tᵢ) · ∂yᵢ/∂θ

The ½ cancels with the 2 from the power rule. Remember:

  • Sum rule: move sum outside derivative
  • Chain rule: ∂f(g)/∂x = ∂f/∂g · ∂g/∂x
  • Constant factor rule: ∂(cf)/∂x = c · ∂f/∂x
Maximum likelihood principle

Choose parameters θ that maximize p(data | θ).

In practice: maximize log-likelihood ln p(data | θ) — log turns products into sums, making optimization easier.

Deep learning minimizes −ln p(data | θ) because frameworks expect a loss to minimize.

Connection: MLE → Least squares

Assuming normally distributed errors, MLE derivation gives you exactly the least squares loss. The squaring is a consequence of the Gaussian assumption.

Linear algebra basics — orthonormal basis

An orthonormal matrix Q has columns that are unit-length and mutually orthogonal: QᵀQ = I.

Key advantage: Q⁻¹ = Qᵀ. The inverse is just the transpose — exact, O(n²), no actual inversion needed.

  • Useful for fast change-of-basis
  • Whitening / PCA after projection
  • Stable numerical computation (no large condition number)
Past exam (final-2022 Q17): "Why do we choose an orthonormal basis?" → "Because the inverse equals the transpose."
Mean = L2 minimizer; Median = L1 minimizer
  • argmin_μ Σ (xᵢ − μ)² = mean → squaring penalises outliers quadratically → mean is sensitive to outliers
  • argmin_μ Σ |xᵢ − μ| = median → linear penalty → median is robust
Past exam phrasing: "The mean is sensitive to outliers because the mean minimizes the SQUARED distances to all instances."
Probability & information theory
Entropy, cross-entropy, KL divergence, Bayes' rule — all tested heavily
Probability basics
p(A|B) = p(A,B) / p(B)
p(B|A) = p(A|B)·p(B) / p(A) [Bayes' rule]
p(B) = Σₐ p(A=a, B) [marginalization]
p(A,B) = p(A|B)·p(B) = p(B|A)·p(A) [chain rule]

Conditional probability table: p(A=1|B=a) = cell(row=1, col=a) / sum of column a.

Entropy — application type
H(p) = −Σₓ p(x) log₂ p(x)
H(p,q) = −Σₓ p(x) log₂ q(x) [cross-entropy]
KL(p,q) = H(p,q) − H(p) [bits wasted]
  • H(p) = 0: distribution is certain (one outcome has prob 1)
  • H(p) = 1: perfectly uniform over 2 outcomes
  • H(p) max = log₂(n): uniform over n outcomes
  • H(p,q) undefined if q(x)=0 but p(x)>0
  • KL(p,q) ≥ 0 always; KL(p,q) ≠ KL(q,p)
Compute −H (positive sum) to avoid sign errors. Check answer intuitively: must be between 0 and log₂(n).
Information gain (decision trees)
I(F) = H(S) − Σᵥ (|Sᵥ|/|S|) H(Sᵥ)

S = current set; v = values of feature F; Sᵥ = instances with value v.

Since H(S) is the same for all features in a given split, just minimize the weighted post-split entropy.

Shortcut: if any subset after split has entropy 0 (all same class), that feature is very good.
Intuition: what entropy measures

Entropy = expected codelength when using optimal code for that distribution.

Low probability → long codeword. If p(x)=0 but we use it as a decoder, codelength → ∞. This is why H(p,q) is undefined when q has zeros where p doesn't.

KL divergence intuition

KL(p,q): you're sampling from p but using q's code. The extra bits per sample (compared to optimal) = KL divergence. It's a distance but not symmetric.

Backpropagation
Scalar, matrix, and multivariate chain rule — always on the exam
Scalar backprop — application type

Break function into modules. Work out local derivatives symbolically. Fill in numerically.

1
Decompose: write f as a chain of simple operations
2
Draw computation graph — identify diamond shapes
3
Write local derivatives ∂(output)/∂(input) for each module
4
Use chain rule (+ multivariate chain rule for diamonds) to combine
5
Fill in numeric values
Multivariate chain rule

When x influences f along two paths (diamond in compute graph):

∂f/∂x = Σ over all paths from x to f
= ∂f/∂a · ∂a/∂x + ∂f/∂b · ∂b/∂x

For f = sin(sin(x)cos(x)):

∂f/∂x = cos(c)[b·cos(x) − a·sin(x)]

where a=sin(x), b=cos(x), c=ab.

Key: you don't need the MV chain rule when taking derivative wrt a weight that only appears on one path (even if x appears on two paths).

Matrix backprop — application type

For module y = Wx + b, given upstream gradient y∇:

b∇ = y∇
x∇ = y∇ᵀ W (= Wᵀ y∇ as column vector)
W∇ = y∇ xᵀ

For f(x) = x²w (Practice Exam A):

∂fₖ/∂x = 2x·wₖ
∂L/∂x = 2x·f∇ᵀw
w∇ = x²·f∇

Key insight: AD engines don't compute full Jacobians (too expensive). Instead, they compute vector-Jacobian products directly.

Lazy vs eager execution
Lazy (static graph)

Computation graph compiled and fixed before training. Faster to run. Harder to debug.

Eager (dynamic graph)

Graph built fresh for each forward pass. Easier to debug. More flexible (PyTorch default).

Why ReLU over Sigmoid in hidden layers?

Sigmoid derivative approaches 0 for large |x| → vanishing gradients → slow learning deep in the network. ReLU derivative is 0 or 1 → no vanishing gradient problem (for positive activations).

Decision trees
ID3 algorithm, information gain, overfitting — application type on exam
ID3 algorithm
1
Start with all data at root node
2
For each feature, compute information gain I(F)
3
Split on feature with highest I(F)
4
Recurse on each subset
5
Stop when: all same class, no features left, or pruning condition met
6
Label leaf with majority class
Information gain shortcut
I(F) = H(S) − Σᵥ (|Sᵥ|/|S|) H(Sᵥ)

H(S) is constant for all features at a given node — just find the feature that minimizes weighted post-split entropy.

Intuition shortcut: find the feature that makes the splits most uneven (most one class on each side). If a split gives all-one-class leaves → entropy = 0 → maximal gain.

Check tallies for symmetry before calculating. If two features have identical (or mirrored) distributions, they have equal information gain.
Overfitting & pruning

Without pruning, ID3 keeps splitting until all leaves are pure → memorizes training data.

Solutions:

  • Post-pruning: grow full tree, then remove nodes that don't improve validation performance
  • Max depth: hyperparameter → tune via validation set
  • Min instances: stop if fewer than N instances reach a node
L1/L2 regularization does NOT apply — decision tree model space is discrete, not a real-valued parameter vector.
Practice: tally method

For each feature, tabulate class counts per value:

Feature X=A: {Yes: 3, No: 1} X=B: {Yes: 1, No: 3}

Check margins: column sums = instances per feature value; row sums = total class counts. If any post-split subset has only one class, entropy is 0 — that feature is likely best.

Fill in margins first, then only tally one cell per sub-table. The rest follows from margins.
Support Vector Machines
Maximum margin hyperplane, support vectors, kernel trick
SVM key definitions
Decision boundary: w·x + b = 0
Margin edges: w·x + b = ±1
Margin width = 2/||w||

Support vectors: points exactly on the margin. Condition:

w·xᵢ + b = yᵢ (where yᵢ = ±1)

Positive points: w·x+b = +1. Negative points: w·x+b = −1.

Classification rule
Predict Pos if w·x + b > 0
Predict Neg if w·x + b < 0

This is the same for all linear classifiers — not SVM-specific. SVMs just find the maximum-margin hyperplane.

To check if x is a support vector: compute w·x+b and compare to yᵢ. Support vector ↔ w·x+b = yᵢ exactly (not just same sign).
Soft margin SVM objective
min ½||w|| + C Σᵢ max(0, yᵢ(w·xᵢ+b)−1)
  • C: regularization parameter. Large C → smaller margin, fewer violations. Small C → larger margin, more violations allowed.
  • Equivalent to hinge loss + regularization
  • Dual form enables the kernel trick
Kernel trick & non-linearity

SVMs are famous for the kernel trick: the dual optimization only depends on dot products x·x'. Replace with k(x,x') to get non-linear boundaries without explicit feature expansion.

Jack (partly right)

SVMs are used for non-linear functions via kernel trick.

Jill (partly right)

Base SVM = linear classifier with max-margin loss.

Naive Bayes & Markov models
Two application types — both on every exam. Master the calculation flow.
Naive Bayes — application type

Generative model: models p(features | class), then uses Bayes' rule.

p(c|x) ∝ p(c) · Π p(xᵢ|c)

Assumption: features are conditionally independent given the class.

1
Estimate p(c) = count(c) / total instances
2
Estimate p(xᵢ=v | c) = count(xᵢ=v, class=c) / count(c)
3
Multiply: score(c) = p(c) · Π p(xᵢ|c) for each class
4
Normalize: p(c|x) = score(c) / Σ score(c')
Laplace smoothing

Problem: if a feature value was never seen with a class → zero probability → whole product = 0.

Solution: add pseudo-observations. The exam specifies adding enough so every value appears once per class per feature (4 pseudo-obs total for a binary 2-feature dataset: FF, TT for each class).

P(xᵢ=v | c) = (count(xᵢ=v, c) + 1) / (count(c) + |values|)
Check: smoothing should change some classifications. If it doesn't, you may have made an error. Trust your calculation over intuition.
Markov model classification — application type

For sequence e = w₁w₂…wₙ and first-order Markov:

p(e|class) = p(w₁|class) · Π p(wᵢ|wᵢ₋₁, class)
p(wᵢ|wᵢ₋₁,c) = count(bigram wᵢ₋₁wᵢ in c) / count(wᵢ₋₁ in c)

Then apply Bayes: p(class|e) ∝ p(e|class) · p(class).

Since denominator p(e) is same for all classes, just compare numerators.

To get full probability: p(spam|e) = p(e|spam)p(spam) / [p(e|spam)p(spam) + p(e|ham)p(ham)]. A lot of factors cancel if you keep fractions!
Probability ratio trick
p(spam|e) / p(ham|e) = [p(e|spam)·p(spam)] / [p(e|ham)·p(ham)]

Denominator p(e) cancels. Ratio > 1 → spam wins. Use this before computing full probabilities to check classification.

Prosecutor's fallacy

p(evidence | suspect) ≠ p(suspect | evidence). Bayes' rule handles the reversal. Prior matters: with a 1% spam prior, even strong evidence for spam can yield <50% posterior spam probability.

Generative models: VAE, GAN, ELBO
Conceptually heavy — and the ELBO derivation is always tested
ELBO derivation — application type
ln p(x|θ) = L(q,θ) + KL(q,p)

Since KL(q,p) ≥ 0:

ln p(x|θ) ≥ L(q,θ) [L is the lower bound]

Key identity used in derivation:

p(x,z) = p(z|x)·p(x) [chain rule of probability]

The derivation always ends with Eq[ln p(x|θ)] = ln p(x|θ) because p(x|θ) is constant w.r.t. z.

EM algorithm

Uses the ELBO decomposition. Since ln p(x) = L(q,θ) + KL(q,p):

  • E step: set q = p(z|x,θ) → KL term = 0 → L = ln p(x)
  • M step: maximize L(q,θ) w.r.t. θ with q fixed

Alternate between E and M until convergence. Used for GMMs (Gaussian Mixture Models).

In VAEs, we can't do the E step exactly (inverting the decoder is intractable) — so we approximate q with a neural network.

GAN

Problem: if you pair random input with random target, generator doesn't know which z maps to which x → mode collapse.

GAN solution: train a discriminator to tell real from fake. Generator tries to fool discriminator.

  • Vanilla GAN: unconditional generation
  • Conditional GAN: input-conditioned generation (e.g. colorization — want stochastic output given input)
  • CycleGAN: unpaired image translation; uses cycle-consistency loss
VAE has no discriminator. GAN has no encoder sampling step or KL loss. Don't mix them up.
Discriminative vs generative models
Discriminative

Models p(y|x) directly. Logistic regression, SVMs, neural classifiers. Better for classification when you have labeled data.

Generative

Models p(x,y) or p(x). Naive Bayes, GMMs, VAEs, GANs. Can generate new samples; can handle missing features naturally.

Sequences, embeddings & recommenders
RNNs, LSTMs, Word2Vec, matrix factorization
Markov models for sequences

Model sequence data by conditioning each token on the previous n tokens.

  • 0th order: p(wᵢ) — bag of words
  • 1st order: p(wᵢ|wᵢ₋₁) — bigrams
  • n-th order: p(wᵢ|wᵢ₋₁…wᵢ₋ₙ)

Good for text generation, spam classification. Limited by fixed-size context window.

RNNs & LSTMs

RNN: hidden state hₜ = f(hₜ₋₁, xₜ). Processes sequences token by token. Suffers from vanishing gradients over long sequences.

LSTM inductive biases:

  • Data is a sequence
  • Each token depends on preceding tokens
  • Many tokens can be forgotten (gating mechanism)

LSTM adds input/forget/output gates → can remember long-range dependencies.

Embeddings: Word2Vec & matrix factorization

Both embed featureless objects (words, users, movies) into Euclidean space as vectors, where proximity = similarity.

v(king) + v(woman) − v(man) ≈ v(queen)

Each object → one vector. Learn by predicting co-occurrence (Word2Vec) or factorizing interaction matrix (collaborative filtering).

Recommender systems

Collaborative filtering: user–item interaction matrix. Matrix factorization learns latent user and item vectors.

Explicit feedback

User gives a rating (1–5 stars).

Implicit feedback

Inferred from behavior (clicks, views, purchases). More common in practice.

Exploration vs exploitation: show recommended items (exploit) vs discover user's new preferences (explore) → connects to RL.

Sequential data evaluation

Crucial: test data must be strictly AFTER training data in time. Never mix temporal order — future data cannot inform the past.

Cross-validation with random splits is invalid for time series. Use walk-forward validation instead.

Ensembles & reinforcement learning
Bagging, boosting, Q-learning, policy gradients
Bagging vs boosting
Bagging (e.g. Random Forest)

Train models on bootstrap samples. Average/vote. Reduces variance. Models train in parallel.

Boosting (e.g. AdaBoost)

Train models sequentially, each fixing previous model's errors. Reduces bias and variance. Models train in series.

Boosting rarely used in research: you'd need to boost the baseline too for a fair comparison. Complicates head-to-head evaluation.
Reinforcement learning basics

Agent takes actions, receives rewards from environment. Goal: learn a policy that maximizes cumulative reward.

Offline learning

Learn from fixed dataset. No interaction with environment.

RL (online)

Agent acts, observes reward, updates. No fixed dataset.

Key difference from supervised: labels are reinforcement signals from the environment, not pre-provided
Why gradient descent is hard in RL
There is a non-differentiable step between the model output (action probabilities) and the reward (environment response).

Policy gradient trick: ∇E[r(a)] = E[r(a)·∇ln p(a)] — rewrites gradient of expected reward as an expectation, enabling Monte Carlo estimation.

Exploration vs exploitation

Always exploiting → get stuck in local optima (never discover better actions).

Always exploring → never use what you've learned.

ε-greedy: take greedy action with prob 1−ε, random action with prob ε.

Q-learning: learn Q(s,a) = expected future reward. Model-free, off-policy.

Concept connections & quick-fire review
Cross-topic links that often show up as combination questions
Key connections to memorize

MLE → Loss functions

Normal errors → least squares. Bernoulli errors → cross-entropy/logistic regression. Both derived from maximum likelihood.

ELBO → EM & VAE

Both optimize L(q,θ). EM does exact E-step (sets q=p(z|x)). VAE approximates it with encoder network qᵥ(z|x).

Entropy → decision trees

Information gain = drop in entropy after split. Optimal split = minimal post-split entropy = most informative feature.

Bayes → Naive Bayes → Markov

All apply p(c|x) ∝ p(x|c)p(c). Naive Bayes: features independent. Markov: sequence, tokens depend on previous.

Cross-entropy → logistic regression

Log loss = cross-entropy between true label and sigmoid output. Gradient = (ŷ−y)x — same form as least squares but different loss surface.

KL divergence → VAE

VAE loss term KL(q(z|x), N(0,I)) forces latent space to be approximately standard normal → enables sampling at test time.

Quick-fire: "Which is NOT…" traps
  • Imputation is NOT normalization — it handles missing values
  • ROC AUC DOES need a ranking; confusion matrix doesn't
  • VAE has no discriminator — that's GAN
  • Boosting reduces bias, not just variance
  • Chaining perceptrons is still linear (composition of linear = linear)
  • Batch normalization normalizes over the current batch, not uniform
  • L1/L2 can't apply to trees (discrete model space)
  • Cost imbalance ≠ class imbalance
